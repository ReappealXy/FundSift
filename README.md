# 东启勘流 · FundSift

面向审计与案件核查的资金流水分析桌面软件项目，供内部使用，使用私有仓库管理。

项目围绕银行、微信、支付宝等来源的流水，规划材料整理、统一并表、金额核对、异常复核、来源追溯和结果导出。目标是让每条记录保留来源，让每次确认留下依据。

**当前版本 0.2.0-preview.4。** 桌面版可导入指定的支付宝账户 CSV、微信交易 TXT 和建行账户 XLSX。支付宝规则 v2 识别已核实的同主体余额转余额宝划转，已有 v1 材料可以主动重导。Excel 底稿格式 v3 单列划转依据。见[规则、操作和验收](docs/19-支付宝内部划转规则v2.md)。
桌面版首次使用从空案件列表开始，原 HTML 演示仍可单独打开。二者共用界面资源并显示各自说明，案件数据互不混用。本轮实现与验收见 [多平台技术预览交付](docs/15-多平台并行导入与勾稽证据阶段交付.md)，[0.1.4 界面细节修复交付](docs/08-0.1.4界面细节修复交付.md)，此前 [0.1.3 事务统计与任务反馈交付](docs/07-事务统计与任务反馈交付.md)、[首屏与导入说明](docs/ui-02-首屏与导入说明.md)、[M0 加固交付](docs/06-M0加固与介绍页修复交付.md) 和 [M0 桌面骨架交付](docs/05-M0桌面骨架与交付.md) 保留对应版本历史。

**G0 准备：** 已建立答案 schema v3、41 项覆盖矩阵（v4）和独立核对工具，支持草稿检查与正式冻结门槛；带尾注的时间区间、非紧邻标记及多义缩写保持含义待核，明确时区标记也不静默换算，非 ISO 币种可通过对应格式已批准的映射确认。运行 `npm run test:g0` 可验证工具；三个具体格式的保守规则已经用户批准，真实副本与独立答案逐行对齐；人工边界逐条裁决、A层抽查和正式冻结仍未完成。审核入口见 [G0 验收契约与核对工具](docs/09-G0验收契约与核对工具.md)，最新变化见 [时间尾注与缩写识别修复](docs/12-G0时间尾注与缩写识别修复.md)。

## 使用桌面版

双击 [FundSift-0.2.0-preview.4-win-x64.exe](dist/FundSift-0.2.0-preview.4-win-x64.exe) 启动便携版。版本和哈希见交付文档。案件库使用 v3，打开更早的工作区时会先完成备份和迁移。

首次进入工作台，先选择准备长期保留的文件夹，再新建案件并填写名称与编号。选择的是软件保存全部案件的位置，不会自动导入其中材料。非空新位置会先确认；误选单个案件或内部文件夹会被拒绝。

打开案件 → 材料管理 → 选择原始材料 → 选择具体格式和文件 → 核对本次处理规则。没有币种列的支付宝/微信材料需根据来源确认人民币；建行仅按原文ISO或获准“人民币元”映射识别。后缀相同不代表模板受支持；不支持的结构会明确报错。

导入先核验归档，再完整发布批次；发布前失败不展示半批数据。完成回执列出写入、待核与无法量化数量；可到流水明细和异常复核页按材料/状态筛选、翻页、查看原文。原始金额标明元/分，标准金额以整数分保存且精确显示。待核没有保存或确认按钮，未知值显示“—”。

没有有效批次的失败材料，可以在「材料管理」点击「重试导入」，使用原归档和原规则再次处理。打开案件时会检查并清理超过 24 小时且无引用的导入暂存。

打开「结果导出」，点击「导出 Excel 底稿」，选择可写的本地 NTFS 文件夹。明细表包含原文、原文金额单位、标准值、来源、摘要、类型、名称和待核原因。「导出说明」记录底稿格式版本、数据版本、各平台笔数和字段来源。未知金额留空，账号和卡号按文本保存。底稿记录规则结果，在 Excel 中编辑不会写回案件。

“关联候选”目前包括微信与建行完整卡号、同币种、同金额绝对值、时间差不超过1秒的线索，以及同本方微信同单号多行。两端原记录都保留；候选有冲突或结果截取会明示，不自动合并、去重或算净额。支付宝余额明细尚未接入导入和候选查询。

单文件上限64MiB；建行仅接受已验证的文本单元格结构，公式、合并、宏、外链等明确拒绝。当前不是大文件流式解析器，未完成百万行性能验收。导入开始后需等待最终结果，系统文件选择和规则确认时可以取消，不提供假的中途取消按钮。

旧库先建立并回读核验备份，再升级案件库v3；工作区索引仍v2。历史业务字段保留，历史币种标为本轮未核验证据。数据位置被移动或磁盘断开时不创建空库替代，请恢复位置再重试。设置在本机用户配置目录，案件与归档在所选位置。

换电脑时先正常关闭软件，再复制整个数据存放文件夹（包括cases、archive与backup）；使用兼容v3的软件，不要只复制case.sqlite。请勿两台电脑同时修改同一份工作区。
## 开发与打包

开发环境需要 Node.js（本轮使用 22.20.0）、npm 和 Windows x64。依赖由 `package-lock.json` 固定；SQLite 原生组件须使用 Electron 对应 ABI，普通 Node 不能直接代替桌面运行环境加载它。

在仓库根目录运行：

```powershell
npm ci
npm start
```

当前源码打开案件会先备份并升级到案件库 v3，保留旧业务字段并取消新记录的币种默认值；工作区索引仍为 v2。旧 0.1.4 EXE 不能打开已升级的案件 v3，请用副本验收或继续使用兼容新源码。此处数据库版本与 G0 schema 版本无关。新预览EXE同样使用案件库v3；原0.1.4的v2行为保留在旧交付记录中。

检查与打包：

```powershell
npm test
npm run smoke
npm run build
```

`npm test` 覆盖界面、桌面桥接、SQLite 存储、迁移、任务状态及底稿回读。`npm run smoke` 使用独立合成工作区验证升级、导入重试、按新规则重导、回源、底稿导出和重开。打包后执行 `node scripts/smoke.cjs dist/FundSift-0.2.0-preview.4-win-x64.exe` 验证便携包。

依赖安装/打包需联网获取官方运行时和原生预编译包；运行桌面版不需要联网。`node_modules`、`dist`、运行产物、数据库和样本目录已排除在 Git 之外。

## 单独体验 HTML 演示

1. 将仓库下载到本地，保留目录结构。
2. 使用外部 Chrome 打开 [code/prototype/index.html](code/prototype/index.html)。无需安装依赖、联网或启动服务。
3. 在软件介绍首页点击「进入示例工作台」，体验案件与流水处理流程。

介绍首页采用白色与淡冰蓝配色，完整显示在一屏内；点击进入后，资金图形向四周退场，工作台逐步浮现。系统设置减少动态效果时直接切换。

「下次打开跳过介绍页」在点击进入时保存选择。如需恢复，在工作台左下角「使用说明」中勾选「打开时显示软件介绍首页」；点击「查看软件介绍」也可重新查看。

HTML 的启动选择保存在当前浏览器。换浏览器、移动文件位置或清除浏览器数据后，可能需要重新设置；它与桌面版用户配置分开。

## HTML 演示中的交互

| 页面 | 已实现的原型交互 |
|---|---|
| 软件介绍首页 | 软件介绍、资金轨迹示意、功能概览、使用流程、进入工作台、启动跳过与恢复 |
| 案件工作台 | 新建与切换示例案件、案件搜索、状态分类、待办跳转 |
| 材料管理 | 文件列表与详情、渠道筛选、登记自选文件信息、添加示例材料 |
| 流水明细 | 搜索、渠道/日期/金额/来源筛选、分页、多选汇总、记录详情与来源定位示意 |
| 异常复核 | 对照原值、人工确认金额与方向、单独处理余额差异、填写处理依据 |
| 结果导出 | 选择范围、预览内容、生成并下载有效 XLSX/CSV 文件、重新下载本次导出快照 |

推荐体验路径：**介绍首页 → 案件工作台 → 流水明细 → 点击记录查看来源 → 异常复核 → 结果导出**。

工作台支持 `Ctrl+K` 搜索；`Esc` 关闭弹窗或流水详情。

## 原型的数据与边界

- 工作台使用完全虚构的合成数据，用来确认界面与操作流程，不代表真实案件的处理结果。
- 演示案件、文件登记和复核结果保存在页面内存中，刷新后恢复初始状态；启动偏好单独保存在浏览器中。
- 自选或拖入的文件只登记名称、大小与类型，尚不读取和解析文件内容。「添加示例材料」用于体验模拟并表流程。
- 金额待核的标准金额保持空值，不作为零计入收支汇总。确认金额与处理余额差异分别保存状态和依据。
- 来源查看目前展示合成记录的位置与字段，尚未接入真实 Excel、CSV 或 TXT 文件的原件定位。
- XLSX/CSV 下载可以实际使用，导出内容来自当前演示记录。该导出实现用于原型体验，尚未验证百万行生产性能。

## 已完成的检查

0.2.0-preview.1通过261项界面断言、214项原生检查及88项G0检查。四份真实材料副本同案保留8105条流水；源码及最终便携EXE各通过三阶段116项桌面烟测。新包实测与哈希见当前交付文档，完整G0人工审核和冻结仍未完成。

0.1.3 代码检查已通过 244 项界面断言及 65 组存储、迁移、范围事务与任务状态检查；新增验证包括两万条无关流水下的索引查询计划、替换写入越界拒绝和长等待后仍保留最终回执。开发态和最终 EXE 各通过 100 项运行检查；从 EXE 提取的 22 个产品文件与源码逐字节一致。结果与校验和见 [0.1.3 交付记录](docs/07-事务统计与任务反馈交付.md)。

0.1.2 已通过 216 项界面检查（50 介绍与偏好＋58 工作台＋46 桌面桥接＋62 新用户流程）、51 组存储/迁移/保护/排队检查，以及 426 项独立 Electron 渲染与键盘断言。开发态和便携 EXE 各通过 79 项运行验证（22 升级＋37 建案与引导＋20 重启与失联）。两种文案在六种准确页面尺寸下均通过介绍页一屏检查。实际 EXE 解包后 21 个产品文件与源码零差异；结果、截图及校验和详见 [0.1.2 交付记录](docs/ui-02-首屏与导入说明.md)。旧版 EXE 和验收证据保持原目录。

HTML 示例导出的 XLSX 曾经结构解析与回读验证，CSV 行数与待核空值也已核对；这些结果属于演示导出，不能当作正式导出验收。

0.2.0-preview.2 通过 277 项界面断言、218 项原生检查和 88 项 G0 工具检查。源码和便携 EXE 各通过 121 项烟测。真实样本底稿已独立回读，当前规模验收为 8,105 条。见[本轮交付记录](docs/17-导入收尾与只读Excel底稿交付.md)。
