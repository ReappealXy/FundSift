# 东启勘流 · FundSift

面向审计与案件核查的资金流水分析桌面软件项目，供内部使用，使用私有仓库管理。

项目围绕银行、微信、支付宝等来源的流水，规划材料整理、统一并表、金额核对、异常复核、来源追溯和结果导出。目标是让每条记录保留来源，让每次确认留下依据。

**当前阶段：M0 加固与真实导入前的存储准备，桌面版 0.1.4。** 支持选择数据存放位置、新建/打开/切换案件和重启保存；已有旧案升级前备份、数据保护、新用户引导与使用说明。已实现更新时间的本地时区显示、限定材料／流水范围的事务统计、真实任务阶段和长等待提醒；本轮修复内容区焦点蓝框、状态与通知重叠、底栏重复说明。真实流水解析、金额引擎、复核与正式导出尚未接入。首版真实流水已确定先处理人民币，外币明确提示且不混入合计。

桌面版首次使用从空案件列表开始，原 HTML 演示仍可单独打开。二者共用界面资源并显示各自说明，案件数据互不混用。最新实现与验收见 [0.1.4 界面细节修复交付](docs/08-0.1.4界面细节修复交付.md)，此前 [0.1.3 事务统计与任务反馈交付](docs/07-事务统计与任务反馈交付.md)、[首屏与导入说明](docs/ui-02-首屏与导入说明.md)、[M0 加固交付](docs/06-M0加固与介绍页修复交付.md) 和 [M0 桌面骨架交付](docs/05-M0桌面骨架与交付.md) 保留对应版本历史。

**G0 准备：** 已建立答案 schema、38 项覆盖矩阵（v2）和独立核对工具，支持草稿检查与正式冻结门槛。运行 `npm run test:g0` 可验证工具；真实样本清点、规则批准和逐笔答案尚待完成。审核入口见 [G0 验收契约与核对工具](docs/09-G0验收契约与核对工具.md)。

## 使用桌面版

双击 [FundSift-0.1.4-win-x64.exe](dist/FundSift-0.1.4-win-x64.exe)。首次进入工作台，先选择准备长期保留的文件夹作为数据存放位置，再新建案件并填写名称与编号。这里选的是软件保存全部案件的位置，不是原始流水文件；选择位置不会自动导入材料。非空新文件夹会先确认，误选单个案件及内部文件夹会被拒绝。编号保留输入外观，仅忽略 ASCII 英文字母大小写判重。

处理时会显示实际阶段；等待超过 15 秒仅提醒仍在处理，不会提前判失败或停止已受理的保存。请等待最终结果，不要重复创建案件或强行关闭。案件“最近更新”按电脑本地时区显示，数据库时间保持 UTC。

旧版 v1 数据首次打开时，先生成经过回读校验的独立备份，再事务升级到 v2；备份按批次保留在对应库旁的 `backup/` 内，不自动删除。旧案存在违规数据或重复编号时明确停止升级，不自动改名、舍入金额或建立空案替代。

案件数据放在所选文件夹；软件启动选择等设置放在本机用户配置文件夹。重新打开软件会读取原保存位置。位置被移动或改名时，应先恢复原位置再重试；本版本没有重新定位入口。0.1.0 不能打开已升级的 v2 数据，请使用 0.1.1 或兼容新版本。

介绍页和工作台均可打开“使用说明”。建案后可到“材料管理”查看格式计划和准备说明；建行 XLSX、微信 TXT、支付宝 CSV 都是计划接入，当前不能导入。请保留原件，不必自行删行或改表头。材料、流水明细、复核与导出页面会说明当前状态。

## 开发与打包

开发环境需要 Node.js（本轮使用 22.20.0）、npm 和 Windows x64。依赖由 `package-lock.json` 固定；SQLite 原生组件须使用 Electron 对应 ABI，普通 Node 不能直接代替桌面运行环境加载它。

在仓库根目录运行：

```powershell
npm ci
npm start
```

检查与打包：

```powershell
npm test
npm run smoke
npm run build
```

`npm test` 包括 HTML 回归、桌面桥接合同、新用户流程、真实 SQLite 存储、范围事务、数据库保护、迁移和任务状态检查；`smoke` 使用独立合成 v1 数据验证升级，再验证建案、重启、说明弹窗、误选位置和真实状态订阅，不读取真实案件。布局检查使用独立 Electron 渲染：`node node_modules/electron/cli.js scripts/check-onboarding-layout.cjs`。打包后执行 `node scripts/smoke.cjs dist/FundSift-0.1.4-win-x64.exe`。本次定向布局检查：`node node_modules/electron/cli.js scripts/check-ui-polish-layout.cjs`。结果见 [0.1.4 交付记录](docs/08-0.1.4界面细节修复交付.md)。

依赖安装/打包需联网获取官方运行时和原生预编译包；运行桌面版不需要联网。`node_modules`、`dist`、运行产物、数据库和样本目录已排除在 Git 之外。

## 单独体验 HTML 演示

1. 将仓库下载到本地，保留目录结构。
2. 使用外部 Chrome 打开 [code/prototype/index.html](code/prototype/index.html)。无需安装依赖、联网或启动服务。
3. 在软件介绍首页点击「进入示例工作台」，体验案件与流水处理流程。

介绍首页采用白色与淡冰蓝配色，完整显示在一屏内；点击进入后，资金图形向四周退场，工作台逐步浮现。系统设置减少动态效果时直接切换。

「下次打开跳过介绍页」在点击进入时保存选择。如需恢复，在工作台左下角「使用说明」中勾选「打开时显示软件介绍首页」；点击「查看软件介绍」也可重新查看。

HTML 的启动选择保存在当前浏览器。换浏览器、移动文件位置或清除浏览器数据后，可能需要重新设置；它与桌面版用户配置分开。

## HTML 演示中的交互

| 页面 | 已实现的原型交互 |
|---|---|
| 软件介绍首页 | 软件介绍、资金轨迹示意、功能概览、使用流程、进入工作台、启动跳过与恢复 |
| 案件工作台 | 新建与切换示例案件、案件搜索、状态分类、待办跳转 |
| 材料管理 | 文件列表与详情、渠道筛选、登记自选文件信息、添加示例材料 |
| 流水明细 | 搜索、渠道/日期/金额/来源筛选、分页、多选汇总、记录详情与来源定位示意 |
| 异常复核 | 对照原值、人工确认金额与方向、单独处理余额差异、填写处理依据 |
| 结果导出 | 选择范围、预览内容、生成并下载有效 XLSX/CSV 文件、重新下载本次导出快照 |

推荐体验路径：**介绍首页 → 案件工作台 → 流水明细 → 点击记录查看来源 → 异常复核 → 结果导出**。

工作台支持 `Ctrl+K` 搜索；`Esc` 关闭弹窗或流水详情。

## 原型的数据与边界

- 工作台使用完全虚构的合成数据，用来确认界面与操作流程，不代表真实案件的处理结果。
- 演示案件、文件登记和复核结果保存在页面内存中，刷新后恢复初始状态；启动偏好单独保存在浏览器中。
- 自选或拖入的文件只登记名称、大小与类型，尚不读取和解析文件内容。「添加示例材料」用于体验模拟并表流程。
- 金额待核的标准金额保持空值，不作为零计入收支汇总。确认金额与处理余额差异分别保存状态和依据。
- 来源查看目前展示合成记录的位置与字段，尚未接入真实 Excel、CSV 或 TXT 文件的原件定位。
- XLSX/CSV 下载可以实际使用，导出内容来自当前演示记录。该导出实现用于原型体验，尚未验证百万行生产性能。

