## 2. 已完成的真实功能

- 本地 Windows 便携 EXE；选择数据存放位置；名称＋编号建案；搜索、打开和切换案件；重启保存。
- 每案 SQLite、工作区索引；编号仅忽略 ASCII 英文字母大小写判重；名称允许重复。
- 已知旧版升级前检查、独立备份、备份回读核验和事务升级；备份按批次保留，不自动删除。
- 案件身份、金额基本类型与方向、归属、有效批次等数据库保护。它们不等于完整金额业务引擎。
- 统计未知时显示“—”；失联时不创建空案替代；误选单案及内部目录会被拒绝。
- 新用户六处引导；介绍页与工作台帮助；介绍页切换动画；桌面与 HTML 演示共用资源、分别说明能力。

0.1.3 本次补齐：

- 案件“最近更新”由 UTC 转换为电脑本地时间显示，非法或缺失值显示“—”，数据库原值不变。这是案件元数据的显示修复，不代表已实现流水交易时间的解析规则。
- `runCaseTransaction(db, record, scope, callback)` 强制声明材料或现有流水范围，事务内校验并维护有效计数；越界、未知摘要基线及异常均拒绝或回滚。完整核验保留为显式 `runCaseIntegrityTransaction`／`refreshSummary`。
- 范围保护包括替换写入不能隐式覆盖其他材料的附属记录；临时保护不逐行写摘要，不改变 v2 数据库结构。
- 已受理操作报告排队、实际执行、检查、备份、校验备份、升级和保存设置；原生窗口分别报告等待选择／确认。超过 15 秒只提醒尚未返回结果，不丢弃写入、不提前判失败。
- 状态订阅受限并可解绑；提示更新不重绘表单；最终保存结果仍由实际请求回执确认。

## 3. 必须保留的能力边界

真实建行 XLSX、微信 TXT、支付宝 CSV 仍是计划接入；金额规则引擎、实际标准化与复核、回源和正式导出尚未开放。HTML 原型使用合成数据，原型能下载有效 XLSX／CSV，不能作为真实案件的正式导出验收。

范围事务目前是未来导入／复核服务的基础接口，不代表桌面软件已经导入真实材料。材料范围仍核对该材料历史批次，诊断仍读全部材料元数据；不能声称每次导入分块都是恒定成本，也没有本轮真实导入或百万行性能结论。

旧版摘要若已失效，或未知状态下没有内部有效小计，需要显式完整核验后再使用范围事务；不会拿未知当零。当前没有新增面向用户的“一键完整检查／恢复”按钮。

任务每秒反馈表示主进程尚未收到最终结果，不证明后台每秒有进展。同步 SQLite 语句期间保留最近实际阶段，没有虚构百分比。当前状态反馈不等于真实导入的取消、断点恢复、队列管理已经完成。

## 5. 请 DeepSeek 重点审核

请先只读审查；需要复验时优先代码检查，使用独立合成案件与证据位置，不继续铺开长时间手测。

1. **事务正确性与范围保护**：基线在写锁内判断；材料／流水声明不能漏写；发布切换只计当前有效批次；待核状态与原因一致；异常全回滚；替换写入、临时触发器与清理是否存在绕过。关注 `code/desktop/hardening.cjs` 和 `checks/hardening.check.cjs`。
2. **实际性能边界**：确认限定查询确实使用材料索引／主键，区分本次范围优化与未来重复分块、解析归档和大规模导入的未验收成本。不能只看 SQL 文本就断定没有扫描。
3. **任务状态与最终结果**：排队／执行／迁移阶段是否真实；中间事件不兑现请求；长等待不抛假失败；失败与关闭仍按真实结果收口；终态停止计时、迟到事件及解绑安全。关注 `main.cjs`、`operation-status.cjs`、`worker-client.cjs`、`worker.cjs`、`migrations.cjs` 和 `preload.cjs`。
4. **界面与时间**：本地时区、跨日和无效值；状态更新是否丢输入、焦点或选区；系统窗口等待是否说清楚；状态不能替代保存回执。关注 `code/prototype/app.js`、`copy.js` 和 `checks/desktop.check.cjs`。
5. **回归与交付可信度**：旧案备份／身份／目录保护仍有效；v2 结构未变；测试没有把合成结果冒称真实业务；EXE 与当前源码匹配。
6. **下一步是否可以进入 G0／M1**：区分当前阻塞缺陷、后续业务设计缺口、用户待决定事项；避免把所有未来功能都列为本轮阻塞。

审核输出建议：先给“可提交／存在阻塞”的结论；每个问题写触发条件、实际影响、文件行号和最小修正建议；最后列下一步必须确认的业务范围。复验数量与静态判断分开，不将未执行项写成通过。
