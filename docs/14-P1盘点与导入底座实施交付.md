## 3. P3a：存储与迁移

入口：[foundation.cjs](../code/desktop/foundation.cjs)、[migrations.cjs](../code/desktop/migrations.cjs)、[storage.cjs](../code/desktop/storage.cjs)。工作区仍为 v2，**案件库升 v3**。这与 G0 的 `schema_version=3` 是两套独立版本号。

- 重建 `fund_flow` 以取消 `currency DEFAULT 'CNY'`。旧字段按原有类型和值搬迁；历史币种标记为 `legacy_unverified`，含义是“历史保留值，本轮未核验币种证据”，不推断它以前是默认填入或错误值。
- 新增双列金额原文、币种原文、完整记录封装，原文不可覆写。归档原件是权威字节；`raw_record.values` 是完整字段值，不能宣称 CSV 解码后的 JSON 就是原始文件字节。
- `format_rule_config` 以 `(rule_id,rule_version)` 绑定，执行配置经过闭合 schema 及金额引擎语义检查，按规范 JSON 计算 SHA256，与批准和冻结联动。生产运行不依赖开发依赖 Ajv。旧批次引用的旧规则不能补装一个新解释；规则变化新增版本。
- 币种证据为原始 ISO、批准映射、已核实 CNY、未知或历史保留值。SQL 函数与 JS 使用相同 trim 口径，未知证据不能静默写成 CNY。**DB 兼容历史记录，不独自判断整行业务是否已确认**；新服务聚合金额、时间、身份和业务状态的全部原因。
- 增加材料结构观察、覆盖分类与批次发布时计数。发布回执计数是当次快照，不冒充以后人工复核后的动态待核数量。
- 新的原文、冻结配置、审计历史与终态回执受到写保护；标准值后续复核的能力未被一并锁死。本轮不开放人工修改入口。

迁移先建立经回读复验的备份，再在事务内安装 v3。按固定旧字段及类型计算逐表逻辑摘要，区分 NULL、空串、整数与文本；重建后再次核对，失败回滚。新增字段与结构另验，不比较升级前后数据库文件哈希。

`verify-legacy-foundation.cjs` 已用**未改动的 0.1.4 EXE 创建的合成工作区副本**验过升级：原有字段逻辑摘要一致、新原文列空、外键完整、源工作区逐字节未变。不是对用户实际在用案件的原地升级。

## 4. 金额、归档与稳定查询

[money.cjs](../code/desktop/money.cjs) 独立于 G0 和 Python 答案生成器。十进制文本使用 BigInt 转整数分，按已声明的 ROUND_HALF_UP 舍入，标准金额输出规范整数文本或 null。D 类负列必须分别声明收入/支出政策；未知语义不自动相减、取绝对值或置零。支持 int64 两端，汇总精确累加后再检查最终范围；超界明确失败。实测消息端口及 JSON 往返仍无损。

[archive-store.cjs](../code/desktop/archive-store.cjs) 区分文件系统归档与 SQLite 发布两个边界：复制前哈希和身份、流式复制计数、复制后复验、fsync、独占创建最终对象及恢复日志。最终对象以哈希命名，从归档字节解析，不把源文件路径当证据身份。

恢复与清理保守处理：清理 helper 要求调用方提供同步实际引用检查，并与导入串行，检查全部历史批次，过宽限期后只清理 staging；本轮尚未接入自动清理调度。**本轮不自动删除最终归档对象**，无数据库引用的最终残留也保留待后续明确策略。日志恢复不自动发布半批；临时 `.new` 日志残留可识别和安全重写。整案复制/移动的用户功能尚未开放，不能据此宣称已经支持搬案。

[flow-query.cjs](../code/desktop/flow-query.cjs) 每页在同一读事务取案件身份、持久 `data_version` 和数据。分页上下文包含案件、版本、筛选哈希、排序与末行键，固定 null 时间靠后、时间、材料、二进制坐标、主键的全序。只读当前 done 批次；同批次标准值变化也使旧页返回 `FS_QUERY_STALE`，要求刷新。游标是查询上下文，不是授权凭证，调用方必须持有案件连接。

## 5. 候选格式与导入服务

[alipay-account.cjs](../code/desktop/alipay-account.cjs) 只识别一个明确的 17 列结构：严格 GB18030 无 BOM 或 UTF-8 有 BOM、完整表头和 CSV 逻辑记录、引号内换行、每行同宽。畸形结构整文件拒绝；业务异常保留并待核。三种原时间、原状态、复合用户信息及全部字段保留。未批准的政策不制造账户身份或已确认记录。

[import-service.cjs](../code/desktop/import-service.cjs) 要求调用方提供已批准规则和时间/账户/状态政策，没有内置或模拟的真实批准。先归档，在专门完整性事务登记冻结配置，再分块材料范围事务写入。坐标唯一、原始数据计数、入库计数及归档哈希一致后，同一事务完成 done 和 current 切换。

同哈希默认拒绝重复，明确 reimport 才新建批次。新批失败、取消、归档变化或重启中断不替换旧 current；半批不能被列表查询到。历史批次的归档引用保持有效。每次政策与配置哈希固定在批次中；标准值当时的解释单独存于完整记录封装的 `derivation`，不与 `values` 原文字段混淆，也不按新规则重新解释历史。

明确打开案件时调用中断恢复，列表刷新不执行这项业务写入；只有本服务解析器版本、批次规则身份、政策与配置哈希和已写行都吻合才标为中断失败。未知旧批次保留并诊断，空案无日志不新增归档目录。恢复结果保存在 store 供后续界面使用，当前没有新增恢复提示界面。

按逻辑坐标回源重新核验本批归档身份和大小，返回原始字段与保存时的解释。来源缺失、被替换或损坏明确报错，不找同名文件顶替。

本候选适配器是**64 MiB 单文件技术预览实现**，先完整解码和检查结构，再异步分块产行；不是流式低内存解析器，也没有完成原 M2 的大样本/RSS 验收。异步产行与数据库分块不能被写成大文件低内存证明。

## 6. 独立答案草稿

[oracle-alipay.py](../scripts/samples/oracle-alipay.py) 使用 Python csv、Decimal 和 datetime，与产品代码和 G0 独立。最新私有输出是 `answers-draft/run-002/`：保留全部原字段与坐标，金额另用整数拆位算法逐行复核，覆盖 7910 个字段与边界断言。
