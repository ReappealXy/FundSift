## 二、架构可行性逐项

| 审查点 | 结论 | 依据 |
|---|---|---|
| Electron + SQLite 支撑百万行 | ✅ 成立 | 两案实测分析态量级：CSV 合计 235 万行（单表最大 19.6 万行）、追踪 SQLite 7.6 万笔；SQLite 单机千万行内无忧；HYJX 22 条规则 SQL 已在 SQLite 22/22 可执行 |
| 19.6 万行 csv 流式解析 | ✅ 成立 | Node 流式逐批入库，无内存峰值问题；xlsx 全量解析才是峰值来源（见问题 3） |
| 整数分存储 | ✅ 成立 | 审计场景必须杜绝浮点误差；HYJX 微信格式原值即「分」，天然契合 |
| 包体 <150 MB | ✅ 成立 | Electron 裸壳约 100 MB + 依赖几十 MB；无 MySQL/Redis/Ollama |
| 界面复用逆向前端资料 | ✅ 成立 | 77 路由/56 段功能描述为需求源，实现用 Web 技术 |
