# G0 审查修复：币种证据与覆盖矩阵 v2

日期：2026-11-18。用户确认实施 DeepSeek 审查提出的币种漏洞修复、两项覆盖补充、`int64` 入口检查及版本同步。本次只修改 G0 开发工具与合成夹具，桌面版仍为 0.1.4；未读取真实流水、填写真实答案或重打 EXE，未执行 Git 提交。

## 1. 变化与原因

| 项目 | 修复后行为 |
|---|---|
| 小写／带空格 ISO 币种 | 将原币种临时 `trim().toUpperCase()` 后比较，`usd`、` UsD ` 均不能被写成 CNY；原始文本不改写，标准 USD 可保留 |
| 无原始证据的外币 | 原始币种为 null 时，不允许凭空填 USD 等外币；缺原文只允许已批准的 `verified_cny` 规则明确声明 CNY。非 ISO 文本本版没有映射契约，保持币种未知、整行待核，不能借 CNY 默认值覆盖 |
| `time_timezone_marker` | 新增独立覆盖项。原始时间含 Z、ISO 偏移（含 `+08`、`+0800`、`+08:00`）或 UTC/GMT 标记时，原文保留，`txn_time=null`、pending，并附 time/timezone 原因；不能静默转换成本地标准时间 |
| `amount_unparseable` | 新增独立覆盖项。N/A、—、全角数字等非空但不能按本版十进制语法解析的金额保持 null、pending，并附 amount/format 原因；单金额类检查 `raw_amount_text`，D 类检查收入／支出列，不能用另一列掩盖无法解析的非空值 |
| `int64` 自身检查 | 在 BigInt 转换前拒绝前导零、加号、空白、负零、小数、非安全数字及错误类型；继续接受规范的 int64 十进制字符串、安全整数和合法 null，不再仅靠 schema 保护调用入口 |

时区与不可解析金额的约束不依赖覆盖标签：删掉标签也不能静默确认。覆盖数量为 **38 项：37 项行级＋1 项文件级**；两个新增项均保持 `min_count=1`。结构字段未新增，`schema_version` 保持 1，`matrix_version` 升为 2。

金额互换但结构仍自洽的答案，仍可能通过工具。这是既有边界：核对工具不生成业务正确答案，也不替代独立规则证据、A 层抽查或 B 层人工裁决。
