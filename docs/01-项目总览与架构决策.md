## 一、背景与定位

- **使用者**：东启会计师事务所审计人员，处理司法审计案件（谭磊被诈骗案、艾仕达合同诈骗案等）。
- **核心工作流**（用户定义，一切功能围绕它展开）：

  接收材料 → 并表 → 对照卷宗核对覆盖范围 → 列缺口补调 → 再分析

- **软件定位**：把上述流程固化的本地桌面工具；第一版做到「并表闭环」，逐步扩展至规则分析、图谱与报告。
- **形态决策记录**（2026-11，用户拍板）：
  - exe 桌面软件；流水数据在本地，处理后导出到本地文件夹；
  - 多人使用 = 每人装一份、各自独立，无账号、无同步；
  - 备选 B/S 服务器形态被否：案件数据不适合出本机。

## 三、架构决策：逆向资料「路线 B」

逆向文档《01-复刻总览与技术选型》给出三条路线，本方案采用其推荐的路线 B 并微调：

| 原系统组件 | 本方案 | 理由 |
|---|---|---|
| Qt 启动器 dm.exe | Electron 主进程兼任（仅 UI 调度；解析与 DB 在 utilityProcess worker） | 少一套 C++ 工具链 |
| MySQL 5.7.36（dmdb） | **SQLite（WAL）** | 百万级实测可行（235 万行合成：写 4s/索引 11s/聚合 0.4s）；「千万行无忧」无证据不承诺；用户零安装 |
| Redis（dmrds） | 进程内缓存 | 单机场景收益低 |
| 双 Spring Boot（fund/admin） | 单 Node 服务（utilityProcess worker 内） | 少一个 JVM；主进程不碰解析与数据库 |
| nginx | 不需要 | 原系统 3.4.11 已移除 |
| Ollama（qwen3） | 第一版不装，留接口 | AI 能力后补 |
| XJar 加密 | 不做 | 加固收益低 |
| Inno 安装包 | electron-builder | 同形态 |

**保留参考对齐的资产**：

- 数据模型以逆向表结构为蓝本，第一片实际采用自建精简表（fund_flow 等，见 docs/03），**不承诺与 HYJX 测试表「银行交易流水」直查兼容**；
- 规则参数与阈值（9 条种子参数、22 条规则参数）——第 4 片落地时须做字段/单位/金额方向适配（兼容视图或重写），逐规则复验；
- 页面功能清单（77 路由 → 界面开发需求源）。

**迁移后门**：未来量级增长或协作需要时，SQLite 可切 PostgreSQL/MySQL；规则查询届时按第 4 片的适配视图迁移，不承诺「SQL 不改」。

## 四、风险与边界

1. **核心算法未证实**：DMSeek 业务 jar 为 XJar 加密，规则/专题算法本体未获源码；现有规则 SQL 是候选，需真实样本验收。
2. **规则命中率**：HYJX 14 条规则在测试数据返回空，不构成充分验证；必须以两案人工核实片段为验收答案。
3. **格式覆盖**：221 格式中多数未与真实文件配对验证；策略是「做一个格式验一个格式」（谭磊案原件即配对样本）。
4. **报告规范**：所内文书格式、签章要求需在第五片前单独确认。
