## 二、两项关键修正

### R1 [高] 原样执行DDL仍直接报错

位置：[03:113](D:/Analyze/FundSift/docs/03-第一片开发计划-并表闭环.md:113)。

fund_flow的表级复合外键夹在列定义之间：

~~~sql
rule_version INTEGER NOT NULL,
FOREIGN KEY (format_rule_id, rule_version)
  REFERENCES format_rule(id, rule_version),
source_loc TEXT NOT NULL,
~~~

本轮用Python标准库SQLite 3.45.1，以foreign_keys=ON原样执行文档SQL，结果：

~~~text
sqlite3.OperationalError: near "source_loc": syntax error
~~~

错误来自约束位置，**不是SQLite不支持该复合外键**。将表级FOREIGN KEY移动到所有列定义之后，与末尾UNIQUE放在一起，再执行可以建库；填入不存在的规则ID/版本组合也会正确被外键拒绝。

最小修订：只调整约束位置，并以“原文完整DDL可以执行＋复合外键能拦截错配”作为M0建库前检查。本轮仅在内存字符串中挪动约束继续探测，未修改设计文件。

### R2 [高] 一批多文件后只重导一个文件，会与有效批次规则矛盾

位置：[03:181](D:/Analyze/FundSift/docs/03-第一片开发计划-并表闭环.md:181)、[03:184](D:/Analyze/FundSift/docs/03-第一片开发计划-并表闭环.md:184)。

current_batch_id属于“文件”，superseded却标记整个“批次”。文档未限定一文件一批；当前DDL也允许一批含多个文件：

1. 批次1成功导入文件甲和文件乙，两者current_batch_id都为1。
2. 只重导文件甲，产生批次2。
3. 按协议把甲的指针切到2，并把旧批次1标为superseded。
4. 文件乙仍指向批次1，违反“有效指针只指done批次”的约定。

探针中，甲旧金额100、乙金额100、甲新金额200：
- 只按当前文件指针查询，合计仍为300；
- 同时执行“当前批次必须done”的条件，合计变成200，乙被漏掉。

这不是说现有指针查询立即漏数，而是**两条文档要求给出了不同的有效数据集合**，后续查询、清理或恢复容易据此误删/漏算。

最小可行选择：第一片明确“一文件的一次解析运行对应一个批次”，批量选择多个文件时逐文件建批次；或者保留多文件批次，把每文件转换版本/有效状态放入文件与运行的关联记录。二选一写清即可，不要求引入更多产品功能。

成功发布还应明确：新批次有效化、current指针切换、旧版本状态更新在**同一事务**内完成；失败、取消或崩溃前后均保持旧有效结果。检查current目标与文件、案件的归属及done状态，可由受控worker写入口和事务保证，也可用数据库约束/触发器保证，不强制采用某一种实现。

本轮额外探测：当前DDL能接受current指向failed或其他案件的批次，fund_flow也能关联到不同案件的文件/批次；因此普通ID外键只保证对象存在，不能单独保证上述业务不变量。把这些拒绝写入场景补入M0/M2探针即可，不应宣称已有FK已覆盖全部关系。

## 三、M1前再明确两处规则

### R3 [中] frozen是标记，不能单独实现“旧规则不可变”

位置：[02:108](D:/Analyze/FundSift/docs/02-金额符号处理规则.md:108)、[03:100](D:/Analyze/FundSift/docs/03-第一片开发计划-并表闭环.md:100)、[03:198](D:/Analyze/FundSift/docs/03-第一片开发计划-并表闭环.md:198)。

临时调整R1语法后，已被流水引用、verified=1且frozen=1的规则，仍可成功执行：

~~~sql
UPDATE format_rule
SET amount_expr='B', unit_scale=100
WHERE id=1;
~~~

复合外键保证版本存在，并不阻止该版本内容改变。当前M1已有“frozen生效”验收方向，可以由worker受控写入口拒绝修改，或由数据库触发器保护；不要求全部写进DDL。

需明确并验证：冻结后的语义字段不能原地改、不能先解冻绕过、变更新增版本，旧流水关联内容保持不变。还应在写入口检查source_unit与unit_scale配对，避免“来源分、倍率100”这种各字段单独合法但组合矛盾的配置。此项属于M1保护机制及拒绝写入测试，不能仅以frozen字段存在判为已实现。

### R4 [中] 判定顺序仍需按金额类别分支，符号冲突不能一刀切

位置：[02:64](D:/Analyze/FundSift/docs/02-金额符号处理规则.md:64)、[02:78](D:/Analyze/FundSift/docs/02-金额符号处理规则.md:78)。

两处文字会让正常行被误送待核：

- 固定每行先映射方向词，未收录就待核；但A类本来没有方向列，D类方向来自金额所在列。应明确A读取金额符号，D读取列位，只有依赖方向字段的类别才执行词表映射。
- 冲突表以“方向=出且金额<0（或反之）”作为矛盾条件，实际上这也可以是正常带符号支出。应按格式规则声明的符号语义比对；已定义格式就按声明处理，未定义或缺少所需信息才待核。建议用具体输入/预期结果替代“或反之”。

D类正常100/0、双非零待核、负值按已验证规则否则待核的修订可保留，无需重写分类体系。
