# 单笔人工复核设计与验收

本轮在已交付的三平台规则导入、支付宝划转和 Excel 规则底稿上增加异常复核写入。首版处理范围由用户确认。

## 复核动作

| 动作 | 适用范围 | 保存内容和结果 |
|---|---|---|
| 记说明 | 当前有效批次的待核记录 | 追加操作人代号、时间、依据。金额、方向和未解除原因按保存前显示 |
| 确认金额方向 | 建行已识别格式中，原文为「借、负额、消费退货」，且存在未解除的 `sign_semantics_undefined` | 保存正数绝对金额和所选收付方向，解除指定原因。其余原因逐项保留 |
| 更正人工结论 | 本批次内已作上述金额方向确认的记录 | 新增一条历史，保留先前金额、方向、依据和操作人 |

异常详情展示来源、规则初始值、当前值、原因和处理历史。操作者选择动作并填写依据。支付宝划转显示「业务性质已定（内部划转），方向待定」，允许记说明。已有底稿 v3 继续输出规则初始值和原始待核原因。导出说明页及入口会提示底稿采用规则结果，软件内可以另看人工结果。

## 历史和事务

历史以材料标识、原件逻辑坐标和原始记录哈希关联。事件还记录批次、流水身份、规则版本、请求标识、前后值和解除的原因。重导前告知当前有历史的记录数，重导后可从材料历史和对应流水查看旧批次结论。前批结论保留在原批次，当前结果沿用新规则。

历史表禁止更新、删除及替换。保存按当前案件、有效批次和 `case_data_version` 校验。相同请求重试只追加一次。金额、原因、状态、案件版本和历史置于同一事务，失败时整体回滚。

## 首轮真实验收

建行第 51 和 52 行的独立期望来自原件余额差，分别为 `2.07 - 0.73 = +1.34 元 / 进` 和 `3.98 - 2.07 = +1.91 元 / 进`。它们只用于验收复核写入。后续是否自动解释这类负额与余额链一致性，需要独立规则验证。

## 回归与独立复验

`npm test` 已通过 294 项界面断言、231 项桌面与数据库测试和 88 项 G0 校验器测试。定向用例检查多原因只解除指定项、追加更正、重复请求、过期版本、历史更新／删除／替换、重导后的来源关联，以及保存中强制结束进程后的整体回滚。桌面烟测从实际界面保存建行确认、重开查看历史，再对支付宝合成材料记说明并按新规则重导，核对材料历史中的旧批次提示。现有案件上下文测试覆盖跨案调用拒绝。

源码版和最终便携版各通过 134 项烟测，覆盖旧版升级 28 项、新建与保存 66 项、重开与重导 40 项。首轮便携烟测发现复核弹窗可能在列表刷新完成前恢复操作，修复后重新打包并通过全部烟测。

便携包 `dist/FundSift-0.2.0-preview.5-win-x64.exe` 为 105,814,689 字节，SHA256 为 `5733850AD40A0A6E4C0B1C274EFA080382C845142EDB2CA1DD6280D3591AEA44`。从 EXE 提取应用归档，35 个产品文件与源码逐字节相同，应用归档中的案件库和验收底稿数均为 0。

复验命令从仓库根目录运行。真实材料复验接收已有规则验收工作区和一个尚未创建的私有输出目录。
