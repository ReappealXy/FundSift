# 支付宝内部划转规则 v2

2026-11-19 · Windows 便携预览版 `0.2.0-preview.4` · Excel 底稿格式 v3

## 业务规则

用户批准将有明确证据的同主体余额与余额宝之间划转保留为账户变动，并排除在经济收入和支出之外。本次实现覆盖现有支付宝 17 列账户 CSV 中已核实的余额转入余额宝场景。

记录须同时满足以下条件：

- 业务状态为「交换产品-余额实时转余额宝成功」，类型为「即时到账交易」，支付方式为「余额」，摘要为「余额宝-自动转入」，收付栏为「其它」。摘要比对容许格式中观察到的一个前导制表符，原文保持原样。
- 本方与对方的完整平台标识原文相同，且是包含数字标识和非空名称的完整文本。只凭名称相同、摘要关键词或状态后缀均不足以识别。
- 划转金额以原始人民币金额核算。可无损转换为正整数分时单独保存绝对值。负数、零、无法无损换算或不可核实金额保留待核。

保存的规则推导记录包含划转路径、核对依据、绝对金额、账户变动标记和经济收支排除标记。已确认的业务性质解除对应的「业务状态不在词表」原因。原件收付栏仍为「其它」时，标准金额和标准方向留空，方向待核继续显示。划转路径用于解释原件记载的账户间变动。余额明细解析、反向划转、双视角自动配对和收益等其他业务类型需要单独验收。

## 已有材料怎样应用新规则

新导入的指定支付宝账户 CSV 采用冻结规则 v2。已有有效 v1 批次的支付宝材料，在材料页选择「按新规则重导」，确认后由软件读取原归档和当时的人民币来源确认，生成独立新批次。新批次发布前会校验原件哈希、新旧逻辑行、坐标与原字段，并复查当前批次。通过后才切换当前结果。旧批次、冻结规则和失败记录继续留档。微信、建行、失败材料重试沿用各自现有入口。

流水和原文详情能查看内部划转分类、账户变动及经济收支依据。底稿格式 v3 单列划转路径、原件绝对金额、账户变动留痕和是否计入经济收支。说明页补齐支付宝两列身份与摘要的前导制表符提示、三个收付标签的当次计数，以及原件「消费名称」也可能记录交易说明的说明。

建议 DeepSeek 重点复核三组反例：同名不同账号、产品名称相似但业务状态或用途不符、原文金额有损或符号异常。重导复核重点是旧批次与原件完整保留、过期批次被拒绝、原件损坏或处理失败时继续显示上一有效批次。各账户视角的证据边界以 [多平台交付证据](15-多平台并行导入与勾稽证据阶段交付.md) 为准。

大白话：软件先看清这笔钱是不是本人余额转进余额宝。能看清的归入内部划转，查账户时有据可查，算赚了或花了多少钱时排除。旧材料可以安全用新规则再跑一遍，原结果留得住。
