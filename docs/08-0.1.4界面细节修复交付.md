# 0.1.4 · 界面细节修复与交付

实施日期：2026-11-18。根据用户提供的 DeepSeek 0.1.3 独立复验意见，修复三处 UI 问题并交付 0.1.4。范围限于界面、验证脚本、版本与交付记录；数据库结构仍为 v2。

## 1. 审查意见与处理

| 意见 | 核对与最终处理 |
|---|---|
| 工作台键盘／程序聚焦时出现整块蓝框 | 全局 `[tabindex]:focus-visible` 优先级确实高于原 `.workspace`。仅对 `main.workspace` 和 `#intro-title` 的 `focus-visible` 去掉 outline；两处仍接收导航焦点，实际按钮、链接等保留可见键盘焦点 |
| 状态提示和 toast 占用同一角落 | 用共享垂直提示栈，让任务提示位于通知上方并随通知实际高度自动排开。未采用固定挪高 40px 的方式，避免多条／多行通知再次重叠；状态隐藏、通知清空后不留空位 |
| 底栏未设位置时重复说明 | 原左右分别为“尚未设置…”和“尚未选择…”，属于同义重复。右侧在没有路径时留空，选择后仍显示实际路径 |

状态提示只显示活动操作，完成／失败后隐藏。本次验证的是“活动操作 + 尚未消失的通知”同时出现的情况，不把完成后的隐藏提示误称为仍然显示。

用户提供的 DeepSeek 结论是 0.1.3 无阻塞缺陷，并独立复验了当时的 244／65／100、包内容和哈希；这些属于外部审查记录。下表是本轮针对 0.1.4 重新执行的结果。
