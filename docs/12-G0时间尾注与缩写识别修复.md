# G0 时间尾注与缩写识别修复：供 DeepSeek 复审

日期：2026-11-18。用户同意将时间标记尾注、区间尾注、非紧邻偏移及固定缩写分类纳入补丁，并授权评估后直接修复。本轮采用版本方案 **A：schema v3、矩阵 v4**，新增第 41 项缩写见证。桌面版仍为 0.1.4；本轮只改 G0 工具、契约、合成夹具与文档，未读取真实流水或生成真实答案，未重新打包 EXE，未执行 Git 提交。

## 1. 结果与判定顺序

时间识别保留原文，不转换时区，也不从区间自动提取端点。先识别完整时间区间（允许后接括号、尾注、备注），再处理多义缩写、完整时区标记和非紧邻偏移；含义不明时保持 `txn_time=null`、pending，原因必须精确为 `time_ambiguous`。明确时区也保持标准时间 null、pending，但要求时间／时区原因，不能仅用 `time_ambiguous` 冒充。

| 原文场景 | 期望分类 |
|---|---|
| `08:00-09:00`、`08:00 - 09:00`、`08:00至09:00` | ambiguous，要求 `time_ambiguous` |
| `08:00-09:00（班次）`、区间后有 UTC／备注 | 区间优先，仍 ambiguous |
| `2026-11-18 23:00 至 2026-11-19 01:00（跨日）` | ambiguous，不取任何端点 |
| `2026-11-18T08:00:00+08:00（北京时间）`、偏移后有“交易” | timezone，保留原文待核 |
| `2026-11-18 08:00:00-05:00 交易` | 保留原有空格负偏移歧义口径，ambiguous |
| `2026-11-18T08:00:00-05:00 交易` | 保留 ISO T 分隔偏移口径，timezone |
| `08:00 备注+08:00` | 非紧邻偏移，ambiguous |
| `08:00 CST`、`08:00 cst` | 多义缩写，ambiguous |
| `08:00 JST` | 名单内明确标记，timezone |
| `08:00 备注JST` | 缩写与时间之间夹文字，ambiguous |
| `08:00Z` | 完整相邻 Z，timezone |
| `08:00 Zebra`、`08:00 BCST` | 不命中时区标记 |
| `08:00 单号123456`、`08:00-123456`、单独的 `2026-11-18` | 不把单号或日期片段拆成偏移 |

不命中标记仅表示本轮没有发现该类原文标记，不证明原始时间可解析或业务答案正确。本工具仍不是通用自然语言时间解析器；普通本地标准时间继续由既有有效日期／时间检查约束。

完整 token 带边界检查，不能把 `-123456` 的前两位或四位当成偏移。Z 仅在时间后相邻（可有空白）且后续不是字母、数字、下划线或时间续串时识别，不能从 Zebra 中截取。非紧邻数值偏移仅在时间出现后检查，并排除紧接数字／冒号的日期或编号片段。斜杠日期、多空格日期、仅小时偏移等既有保护保留。

完整两个时间端点先判区间；已有 `日期T时间-HH:mm` 紧凑写法仍按明确 ISO 偏移处理。两者字面可能存在歧义，这是已批准的契约取舍，不代表工具验证了真实格式语义。两种分类均保持待核，差别是原因与覆盖见证。

## 2. 固定缩写名单

| 处理分类 | 名单 | 原因要求 |
|---|---|---|
| 多义，ambiguous | CST、IST、EST、PST、BST、AST、GST、MST | 必须有独立 `reason_code=time_ambiguous` |
| 明确标记，timezone | UTC、GMT、JST、KST、HKT、SGT、AEST、AEDT、CET、CEST、MSK | 有包含 time／timezone 的原因，且不能仅为 `time_ambiguous` |

名单是本契约约定的处理方式，不断言任何缩写在全球具有唯一含义。匹配大小写不敏感、使用完整 ASCII 单词边界，BCST、CSTfoo 等不能作为见证；中文备注可以作为边界。区间或夹有文字的非紧邻标记优先按 ambiguous，不能因为同时出现 JST／UTC 就忽略区间。名单外文本不自动扩展，不自动推断时差或换算成本地时间。

## 3. 第 41 项不是空标签

矩阵新增 `time_zone_abbreviation`，行级，`min_count=1`。见证必须同时满足：

- 原始 `txn_time_text` 确实命中名单内完整缩写，不能用数值偏移、Z 或无关文字凑数。
- `expected.txn_time=null`、`status=pending`。
- 原因与最终分类一致：ambiguous 必须有精确 `time_ambiguous`；timezone 必须有其他符合时间／时区要求的原因。

两类缩写共用一个覆盖项，正式最低要求仍为 1；本轮完整冻结合成夹具额外放入 **JST、CST 两条**已批准 B 层见证，回归分别验证两类正确原因及错误原因拒绝。`time_timezone_marker`、`time_ambiguous` 继续检查各自真实条件，不能互相贴标签替代。删除标签也不能静默确认带标记时间。

原有币种映射语义保留：普通行按已批准格式规则机械生成，可使用 A 层并挂 `amount_a`；承担 `currency_mapped_cny` 等边界覆盖的见证行须进入 B 层。没有把全部映射行强制改为人工逐笔裁决。真实规则卡应把币种映射单列一节，明确原文、标准币种、文件依据与批准人；当前规则级 `review` 覆盖映射，本轮没有新增第二套签字字段。

## 4. 版本方案 A 与迁移

| 项目 | 上轮历史 | 本轮 |
|---|---|---|
| `schema_version` | 2 | **3** |
| schema `$id` | `bundle-v2` | **`bundle-v3`** |
| `matrix_version` | 3 | **4** |
| 覆盖数量 | 40：39 行级＋1 文件级 | **41：40 行级＋1 文件级** |

schema 中 `schema_version.const=3`、`matrix_version.const=4` 固定当前组合，工具没有将版本校验挪走。虽然业务字段未新增，这次修改了 schema 中的矩阵版本常量，因此同时发布新的 schema v3，明确该版本对应新的内容。旧 schema v1/v2 或矩阵 v1/v2/v3 均由 SCHEMA 拒绝；schema、矩阵及 bundle 哈希继续独立固定。没有以同一个 schema v2 版本号覆盖本轮新内容。

已有冻结基准须另存新的 `dataset_version` 与目录，按新时间口径重审受影响答案、原因和见证，复核批准，再固定 schema、矩阵、答案、生成器与外部 bundle 哈希；规则变化另增 `rule_version`。保留旧文件、旧哈希和旧审批，不能仅替换版本数字就沿用旧结论。前两轮历史记录分别保留于 [币种与覆盖补修](10-G0币种与覆盖补充修复.md)、[时间歧义与币种映射](11-G0时间歧义与币种映射.md)。
