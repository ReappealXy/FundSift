# 导入收尾与只读 Excel 底稿交付

2026-11-19 · `0.2.0-preview.2`

本页为首版历史记录。首版底稿已由格式 v2 替代，原文件留档。核对时请使用[底稿格式 v2 交付记录](18-Excel核对底稿格式v2.md)所列版本。

打开案件后，在「材料管理」可以重试失败材料，在「结果导出」选择「导出 Excel 底稿」并指定保存文件夹。底稿包含「流水明细」和「导出说明」两张表。当前交付沿用三平台技术预览的规则，单笔人工复核、业务口径调整和正式并表导出属于后续阶段。

## 导入收尾

- 没有有效批次的失败材料可以使用原归档和冻结规则重试。重试追加批次并保留失败记录。已有有效批次的材料继续适用普通重复导入检查。
- 打开案件时检查导入暂存。超过 24 小时、没有活动任务且确认无引用的暂存才会清理。最终归档和无法核验的恢复清单保留。
- 材料页显示中文格式名称，并单列含附加诊断的流水数。流水页在 1024×720 窗口保留原文入口与待核原因。原文对话框显示金额单位、舍入与符号处理依据。
- 归档归属通过 `import_batch.archive_entry_id` 和 `source_file.archive_entry_id` 追查。旧反向列的持久触发器随 v3 结构保留以兼容现有案件库，业务查询和写入范围判断依照正向引用。已验证仅凭旧反向列无法授权写入。

## Excel 底稿

流水明细使用与案件统计相同的有效批次范围，保留每笔来源记录。文件名含数据版本和 UTC 时间戳。生成文件前读取同一快照，写完后复查版本，完整文件原子发布。保存目标须支持硬链接，建议选择可写的本地 NTFS 文件夹。同名文件保留，超出 Excel 单页或单元格容量时中止并提示。进程被强制终止或断电时，保存目录可能留下 `.tmp`，最终 `.xlsx` 文件名只用于已完整写出的文件。

| 内容 | 在底稿中怎么核对 |
|---|---|
| 案件和来源 | 案件编号、名称、材料名、平台、原件文件名及 SHA256、批次、格式和规则版本、原始坐标及工作表行号或逻辑记录号 |
| 原文和标准值 | 并排看原始金额与标准金额、原始方向与标准方向、原始时间与标准时间。另有原始余额、原始币种和标准币种依据。微信接收金额与主金额分别保留 |
| 精度 | 账号和卡号按文本入表。已知标准金额按元显示两位小数，超过 Excel 精确数值范围的金额用两位小数文本表示，未知金额留空 |
| 状态与证据 | 业务状态原值与规则归一值、资金流判断、证据状态、全部未解除原因及说明、换算依据。派生的「是否计入收付」提供是、否、未知三种提示 |
| 说明页 | 数据版本、导出时间、全案与分平台笔数、原因码含义、未入表材料与状态。底稿为规则结果，Excel 内修改不会写回案件或形成复核记录 |

说明页仅统计笔数。默认导出整个当前案件的有效流水，保留待核行和各个来源视角。底稿数据可用 Excel 的表头筛选继续核查。
