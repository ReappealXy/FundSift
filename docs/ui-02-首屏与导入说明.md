# UI-02 · 首屏与导入说明

> 日期：2026-11-14。用户已授权按交叉审查意见实施；目标桌面版本：0.1.2。
> 以 0.1.1 的真实能力为基础，增加新用户引导和误选案件内部文件夹保护；真实流水导入等功能仍未接入。
> 本轮六处引导共享 `code/prototype/copy.js`；原生选择框与底层错误由桌面模块产生。下文保留评审依据与文案约定，实际交付证据在第 10 节登记；不把计划中的验收写成通过。

## 1. 要解决的问题与范围

第一次打开软件，使用者应当能回答三个问题：软件现在能做什么、眼前这一步要选什么、完成后下一步去哪儿。不能要求使用者先理解数据库、工作区或开发阶段编号。

本轮修改：软件介绍页、首次选择保存位置、案件工作台、新建案件、材料管理、使用说明与操作反馈。沿用现有页面和使用说明入口，在正要操作的位置提供简短提示，详细说明按需展开。不新增强制教程或每次启动都必须点完的引导流程。

真实导入、人工复核、流水查询和正式导出仍未接入；不能通过增加文案、文件选择框或灰态区域，把这些功能描述成已经可用。

### 1.1 对本轮外部建议的处理

| 建议 | 实施处理 |
|---|---|
| 同一份页面按 EXE／网页演示显示不同文案 | 采纳；不能复制两份页面，也不能把 EXE 中的真实案件管理说成合成数据演示 |
| 介绍页少量状态说明、细节展开、一屏复测 | 采纳；规划中的功能必须就地标识，不能只在页脚补一句 |
| 首次选位置解释旧版升级可能需要等待 | 采纳，但写明先检查、通过后备份升级；不承诺任何旧文件夹都能升级 |
| 灰态导入区与三行格式表 | 采纳为界面方案；三种格式全部标为“计划接入”，其余格式不能写“先登记” |
| 导入前自查五条 | 调整为保留原件、准备来源信息等说明；不要求删合计行、取消合并、拆分文件或补造字段 |
| 六处共用文案来源、复用现有检查 | 采纳；检查还必须覆盖运行模式、操作反馈和键盘行为，不能只搜关键词 |
| 保存位置失联后重新选择；失败后显示备份路径 | 当前不具备，不写成现成操作；是否新增恢复入口另行确认 |

## 2. 能力事实与用词

### 2.1 当前能力和后续计划

| 项目 | 0.1.2 能力边界 | 页面可以怎样写 |
|---|---|---|
| 数据保存 | 首次选择本地文件夹，后续按已保存路径读取 | 选择数据存放位置；下次继续读取这里的案件 |
| 案件管理 | 创建、保存、打开、切换案件，关闭后保留 | 当前可用 |
| 旧数据升级 | 已知且检查通过的旧版数据会先生成并校验备份，再执行升级；未知结构拒绝打开 | 发现兼容旧版案件时可能需要等待 |
| 材料登记与导入 | 未接入，不读取或登记用户选择的材料 | 开发中；本版本暂不能导入 |
| 首批格式 | 计划打样建行 XLSX、微信 TXT、支付宝 CSV；尚未完成真实导入验收 | 首批计划接入，不是已支持格式清单 |
| 流水查询、复核、导出、行级回源 | 尚未接入真实案件操作链 | 开发中，不提供可执行的假入口 |
| PDF／Word／图片 | 没有自动流水解析，也没有“仅登记留档”能力 | 不在本轮自动流水解析范围；不承诺材料归档功能 |
| 币种 | 用户已确认后续首版只处理人民币；真实入口尚未实施 | 接入后仅处理人民币，外币明确提示且不计入合计 |
| 备份保留 | 升级备份按批次保留，不自动删除 | 不增加自动清理或一键恢复承诺 |

### 2.2 术语表

| 界面统一用词 | 含义／适用位置 | 应避免的含混说法 |
|---|---|---|
| 数据存放位置 | 软件保存案件数据的位置；需要选择时明确说“文件夹” | 资料文件夹、数据目录、仓库、工作区 |
| 案件材料 | 用户提供的原始文件；材料页可具体写“原始流水文件” | 资料、附件、把所有文件统称数据 |
| 流水明细 | 后续统一整理后的逐笔流水；原“并表流水”导航显示名已改为此词，内部路由不变 | 并表记录、记录表混用 |
| 文件夹 | Windows 上可选择或恢复的位置 | 目录与文件夹交替使用 |
| 案件工作台 | 案件列表和当前案件的入口 | 此名称可以保留，不等同于内部“工作区” |

内部字段、错误代码、数据库名和维护文档可以保留原技术术语。界面主提示应说人话，诊断详情保留真实原因；不要全局替换技术文本而改变错误含义。

|---|---|---|

桌面模式不出现“HTML 交互原型”“工作台使用合成数据”；网页模式继续明确演示属性。概念插图仍是示意图，不删除其真实性说明。当前桌面材料页本来就没有可操作的导入入口；本轮是增加清晰说明，不将此前状态误记为“拆除假入口”。

### 3.2 首次选择数据存放位置

**默认显示：**

> **先选择数据存放位置**
>
> 软件会把你创建的案件数据保存在这里，方便下次打开继续使用。请选择一个准备长期保留的文件夹。
>
> 这一步只设置保存位置，不会导入文件夹里的流水。Excel、CSV 等原始流水文件，后续将在案件的“材料管理”中另外选择。
>
> **选择存放文件夹**
>
> 当前可用：创建、保存和打开案件。流水导入等功能开发中。

对应键：`COPY.setup.title`、`body`、`inputNote`、`choose`、`status`。

**“已有旧版案件？”展开说明：**

> 如果你已经使用过本软件，请选择原来保存全部案件的文件夹，不要选择 cases 文件夹、某个案件自己的文件夹或原始流水文件夹。
>
> 软件会先检查现有数据；检查通过且需要升级时，会先生成并校验备份，再执行升级。可能需要等一会儿，请等待完成，期间不要强行关闭软件或移动文件夹。
>
> 无法识别的版本或检查未通过的数据会停止打开，并说明原因。不要删除原文件后重新创建空案件。

**误选位置保护：** 检查和实际打开均在写入前拒绝单个案件、其 archive／exports 等内部位置，以及可确认属于本软件的 cases 容器。提示选择“保存全部案件的数据存放文件夹”；不写成“上一级”，因为单案的上一级通常只是 cases。判断依据是本软件数据身份或案件结构，普通同名文件夹不因名字被拒绝。确认后结构发生变化也再次检查；失败不创建嵌套空数据。系统文件夹选择器自身创建文件夹的动作不属于软件检查写入。

“旧版”指本软件兼容的旧版数据结构，不是任意银行文件或其他软件的案件文件夹。未知版本、损坏文件不承诺可自动升级。

**选择非空新文件夹的系统确认框：**

> **在这里保存案件？**
>
> 这里已经有文件，是否仍在这里保存案件？
>
> 数据存放位置：`{candidate}`
>
> 软件会新增案件数据文件和案件子文件夹，已有文件会保留，不会导入其中的流水材料。建议选择单独、准备长期保留的文件夹。
>
> 将新增 workspace.sqlite 和 cases 文件夹。

按钮：**在此创建／重新选择／取消**，默认选择“重新选择”，沿用现有确认与再次检查机制。

末行技术详情只说明将写入什么，不要求使用者理解内部结构。已有兼容软件数据时按打开／升级流程处理，不能误报为新建确认；索引丢失、冲突或损坏不能靠确认强行覆盖。

### 3.3 案件工作台

按照当前状态显示下一步，避免所有人都看到同一段提示。

| 状态／文案键 | 提示 | 已有操作入口 |
|---|---|---|
| 未选择保存位置 `COPY.home.needLocation` | 先选择数据存放位置，再创建第一个案件。 | 选择存放文件夹 |
| 已选择、尚无案件 `COPY.home.noCases` | 数据存放位置已设置。点击“新建案件”，填写名称和编号即可保存。 | 新建案件 |
| 已有案件 `COPY.home.hasCases` | 从下方列表打开已有案件，或新建一个案件。 | 案件列表／新建案件 |
| 有当前案件 `COPY.home.currentCase` | 当前案件已保存在本地，下次可从案件列表继续打开。 | 打开案件 |

保存位置栏统一显示：**数据存放位置：`{workspacePath}`**。路径过长时可省略显示，但应能查看并选择完整文本，不添加不存在的“打开文件夹”按钮。

统计旁常驻短说明：

> **“—”表示统计尚待检查；具体原因见对应案件的数据状态。**

> 工作台统计用于概览；真实流水查询、正式汇总与导出尚在开发中。

区分空案件的真实 0、统计不确定的“—”和读取失败，不能把它们统一显示成 0。“打开案件可查看完整错误详情”不是当前保证；部分问题会导致案件无法打开，应在列表保留具体原因。

### 3.4 新建案件

标题：**新建案件**。在字段旁解释，不把要求全部塞进提交后的错误提示。

| 字段／文案键 | 标签、示例与提示 |
|---|---|
| `COPY.case.nameLabel` | 案件名称 |
| `COPY.case.namePlaceholder` | 例如：某公司资金核查 |
| `COPY.case.nameHint` | 必填，最多 40 个字符；不同案件可以使用相同名称。 |
| `COPY.case.numberLabel` | 案件编号 |
| `COPY.case.numberPlaceholder` | 例如：DQ-2026-019 |
| `COPY.case.numberHint` | 必填，最多 30 个字符；在当前数据存放位置内不能重复。英文字母 A–Z 不区分大小写。 |
| `COPY.case.location` | 将保存到：`{workspacePath}` |
| `COPY.case.submit` | 创建案件 |
| `COPY.case.saving` | 正在保存… |

编号补充说明：`abc-01` 与 `ABC-01` 视为同一编号；名称可以重名，编号不能重复。首尾空格会去掉，不擅自转换全半角或其他文字。

实施时沿用当前长度校验规则，不因“40 字”措辞擅自改变字符计算方式；罕见字符等边界按既有实现核对。保存位置可能很长，允许该行换行，不能把表单按钮挤出可操作区域。

成功后沿用进入材料页的现有路径，并提供反馈：

> **案件已保存，下次可从案件列表继续打开。**

不增加类型、备注、编辑、归档、删除等本轮未授权字段或功能。

### 3.5 材料管理页

**顶部默认显示：**

> **材料管理**
>
> 流水导入开发中
>
> 这里将用于添加银行、微信、支付宝等渠道导出的原始流水。本版本暂不能导入或保存案件材料，你可以先查看下方准备说明。

对应键：`COPY.materials.title`、`body`。

已显示一个不可导入的灰态区域，标题为 **“导入案件材料 · 开发中”**，旁边常驻 **“当前不能选择或拖入文件”**。不显示可用的文件选择／开始导入按钮，不打开文件选择器，不登记文件名，不模拟成功。

不能仅靠灰色或悬浮提示说明不可用原因：键盘用户、触屏用户也应直接读到“开发中”。详细准备说明可以展开，格式表和当前状态不折叠。

**首批计划接入格式：**

| 材料来源 | 文件类型 | 当前状态 |
|---|---|---|
| 建设银行 | `.xlsx` | 计划接入具体流水模板，尚未完成导入验收 |
| 微信账单 | `.txt` | 计划接入具体导出格式，尚未完成导入验收 |
| 支付宝账单 | `.csv` | 计划接入具体导出格式，尚未完成导入验收 |

表下注：

> 文件后缀相同，不代表内容格式相同。正式开放时，以实际验证通过的具体模板为准。
>
> 其他银行或版本的 Excel、CSV、TXT，当前不能保证识别，也不提供“先登记、暂不解析”。

**展开标题：“提前准备哪些材料？”**

1. 优先准备银行或平台直接导出的原始流水文件；保留原件，不要先删行、改金额、改表头或重新排序。
2. 尽量记录材料来自哪个银行／平台、对应账户和时间范围，方便后续核对。不要为补齐字段而编造信息。
3. 不要因文件带有表头、说明行、合计行或合并单元格就自行清洗原件；是否可读由具体模板的解析验证决定，不能保证所有版式都支持。
4. 加密、密码保护或损坏文件可能无法读取。保留原件，按银行／平台允许的方式另行取得可读取的导出副本。
5. 本版本不读取压缩包，请自行保管原件。后续导入是否需要手动解压，待功能接入时再说明。

内部范围说明：本轮不加入压缩包读取或自动解压，也不把“先解压后导入”写成当前操作要求；后续接入真实导入时再确定操作步骤。

补充说明：

> 金额、交易时间、账户、交易对方等信息会影响识别和核对；缺失时应按具体格式说明问题，不把所有字段都齐全写成通用硬门槛。能够完整保留的异常记录如何进入待核，沿用后续业务规则。
>
> PDF、Word、截图不是本轮计划接入的自动流水解析输入；本版本也不提供“只登记留档”。
>
> 后续首版仅处理人民币；外币将明确提示，不计入人民币合计。币种不明确时，不默认当成人民币。

**样例与批量选择的边界：**

- 示例表头只用于帮助辨认来源，不要求使用者改写原件。本次不编造三家平台的通用表头或具体导出菜单；须待真实模板核对后再补可用示例。
- 一份文件单独保留身份和处理结果，不等于只能一次选一份。后续多选文件仍可逐文件登记和反馈；本轮文案不承诺已实现批量导入。
- 本页保留现有“返回案件工作台”和“使用说明”入口；不新增材料登记、OCR、字段映射等功能。

### 3.6 使用说明与操作反馈

沿用现有“使用说明”弹窗，介绍页也增加同名入口；同一运行模式下两处复用内容，不能出现两套能力口径。以下正文仅用于 EXE 桌面模式，弹窗按三个问题组织：

**当前能做什么？**

> 当前可以选择数据存放位置、创建案件、打开和切换案件。案件名称与编号保存在本机，下次可以继续打开。
>
> 流水导入、流水明细查询、异常复核和正式导出开发中。本版本暂不能导入或保存案件材料，也不会生成流水分析结果。

**下一步做什么？**

> 第一次使用：选择存放文件夹 → 新建案件 → 查看材料准备说明。
>
> 已有案件：从案件列表打开。原始流水后续会在“材料管理”中另外选择，设置保存位置不会自动导入文件。
>
> 当前数据存放位置：`{workspacePath}`；尚未设置时显示“尚未选择”。

**出了问题怎么办？**

> 看提示中的具体原因。文件夹被移动、改名或断开时，先恢复原保存位置，再重试读取。
>
> 检查或升级失败时，保留整个数据文件夹和错误信息，不自行删除、覆盖案件文件；需要时联系维护人员。
>
> “—”表示统计尚待检查，具体原因见案件列表。不要把“—”当成零。

保留“打开时显示软件介绍首页”的现有设置；解释这是本机启动偏好，不改变案件保存位置。保留键盘快捷键说明；不宣称自动同步、云端备份或一键恢复。

**换电脑时怎么带走案件？**

> 正常关闭原电脑的软件，等待保存和关闭完成后，复制整个数据存放文件夹；不要只复制某个案件或 case.sqlite。保留原文件夹，先确认副本可用。
>
> 在新电脑上使用兼容版本的软件，首次设置时选择复制后的整个文件夹；需要足够空间与可写权限。启动选择需要重新设置，文件夹内已有的升级备份随整份复制一起带走。
>
> 这是手动复制，不是自动同步；不要两台电脑同时修改同一份数据。已配置保存位置的电脑仍没有重新定位入口。

验证仅覆盖独立合成数据关闭后整份复制到另一个根位置再打开，身份和统计保持一致；不冒充已完成其他实体电脑、系统和网络共享环境的兼容性验收。

网页模式使用对应的演示说明：“这里使用合成数据体验页面；刷新后恢复初始状态，不会保存真实案件，也不能选择本机案件数据存放位置。”网页中的文件选择只属于演示行为，不宣称真实解析或持久保存。同一份帮助组件按环境选择内容，不能把 EXE 的保存能力套到网页演示。

## 4. 反馈必须匹配真实状态

显示原因及下一步，不用同一句“操作失败”覆盖所有情况。下表记录反馈口径，按实际结果和错误代码匹配。SQLITE_FULL／READONLY／CANTOPEN 具体码传回时会追加对应提示；部分错误已被存储层包装为 FS_*，此时保留实际中文原因，不宣称所有磁盘或权限失败均能精确分类。

| 真实状态 | 建议文案 | 不能承诺的事 |
|---|---|---|
| 首次选择已取消 | 已取消选择。准备好后，可点击“选择存放文件夹”。 | 不能说已设置或正在导入 |
| 读取中，尚未知是否升级 | 正在检查案件数据，旧版数据可能需要备份升级，请稍候。 | 不能把整个等待过程说成“正在升级”，不编百分比 |
| 明确收到升级阶段事件 | 正在备份／正在检查备份／正在升级，请等待完成。 | 当前没有该事件链；不把这组三阶段文案写成已经能显示 |

## 6. 布局、可达性与后续验收

本节是验收清单，实际执行结果在第 10 节登记；不沿用旧版截图或检查数字宣称新界面通过。

### 6.1 页面与键盘

- 介绍页默认保持一屏；优先使用一行版本状态和流程状态标识。长说明放入可关闭的说明层，不靠裁切隐藏文字维持“无滚动”。说明层自身允许滚动，按钮和关闭入口始终可达。
- 展开项使用原生 `details/summary`，或使用带 `aria-expanded`、`aria-controls` 的按钮；状态随展开／收起同步，Tab、Enter、空格可操作，键盘焦点可见。
- 从介绍页打开使用说明时，不能被现有介绍页逻辑隐藏或设为 inert；弹窗打开后焦点进入，关闭后回到原入口，Esc 可关闭，背景不能误操作。
- “开发中”与不可用原因应始终可读，不能只靠灰色和 hover。实际原生 disabled 控件不必强行加入 Tab 顺序，但附近说明可被辅助技术读取。
- 长路径、较长案件名、错误原因不能覆盖按钮；不同宽度下允许说明和内容区合理换行或滚动。
- 保留已有介绍页跳过偏好、返回介绍、减少动态效果和进入工作台后的焦点行为。

上轮提出的事务默认全量校验、worker 长任务超时／进度、失败升级重复备份属于后续存储与任务链设计；本轮未悄悄更改。正式接入导入前须处理批次发布校验与性能，升级备份仍按批次保留，不自动删除。

大白话：这次把“保存案件的位置”和“以后要交的流水文件”说开了，点错位置会拦住；说明随时能打开，不能用的功能明确写清，新包也已实跑验证。
